## 当前策略

当前 `rough_model_7850.pt` 来自第三方 [Zhefan-Xu/isaac-go2-ros2](https://github.com/Zhefan-Xu/isaac-go2-ros2/tree/isaacsim-4.5/ckpts/unitree_go2)，不是宇树官方发布的预训练模型。实际文件6881323字节，SHA256为 `d435f46dcf2d614cad28e21e033b34d6036d079924e1746530a36f2fba2315bd`，与仓库下载器声明一致。

它采用235维输入（48维本体状态加187维高度）、12维动作、0.25动作尺度。当前运行使用50 Hz推理和200 Hz显式电机控制。实测表明持续行进和侧移可以跟踪，但启停及小幅调整仍会出现显著姿态波动；上层恢复停稳检查也存在独立缺陷，不能只凭失败视频归因于权重。

## 不能直接互换的接口

| 项目 | 当前第三方rough | 官方RL Gym Go2 | 官方RL Lab Go2 |
|---|---|---|---|
| Actor输入 | 235维 | 当前代码48维，无拼接高度输入 | 45维，不含基座线速度和高度 |
| 角速度缩放 | 1.0 | 0.25 | 0.2 |
| 关节速度缩放 | 1.0 | 0.05 | 0.05 |
| 动作尺度 | 0.25 | 0.25 | 0.25 |
| PD参数 | 25 / 0.5 | 20 / 0.5 | 25 / 0.5 |
| 推理 / 物理频率 | 50 / 200 Hz | 50 / 200 Hz | 50 / 200 Hz |

原策略在v146的两次接近失稳窗口内没有非地面接触，说明这两次问题并非撞箱后才发生；这仍不能单独区分权重、速度指令组合和部署因素。见[接触时序证据](data/go2_contact_onset_review_v146.json)。

必须依据导出的部署配置核对关节顺序、归一化和电机模型，不能因动作数相同就直接加载。RL Lab的Go2HV执行器还使用自己的分段转矩—转速曲线（X1=13.5、X2=30、Y1=20.2、Y2=23.4），与当前简化DC曲线不完全相同。

官方RL Lab主线README要求Isaac Sim5.1 / Isaac Lab2.3。服务器当前运行环境为Isaac Sim4.2.0.2、Isaac Lab包2.0.2、Python3.10.19，未提供`isaaclab_rl`包。采用官方训练路线应使用隔离环境或明确适配的旧分支，避免改变当前实验依赖。

## 建议和后续验收

值得把官方RL Lab作为下一条对照路线：它包含站立样本、水平姿态、动作变化和足端滑动等训练约束，适合检验当前启停问题。但这些配置不能代替训练好的权重，也不保证推箱接触稳定；Go2任务本身还惩罚头部非预期接触。

先获取可信的Go2权重及其部署配置，或按固定官方版本训练；然后在相同Go2资产、地面和物理条件下对照直行—停止、左右侧移—停止、大角度转向—停止和受力推箱。记录速度误差、姿态峰值、制动漂移和跌倒情况。短动作通过后，再运行原始MV7的T04/T05并核验完整视频、在线地图、新通路穿越和原目标停稳。若修改执行器模型，必须单独记录，不能把模型和策略同时变更后的收益全部归因于policy。

已完成官方源码和接口核查；没有启动官方策略训练，也没有将第三方/NVIDIA权重称作宇树出厂策略。历史T04 v119与T05 v127的单独成功不能合并为当前同版通过记录，当前原始任务状态见 [最新结果](go2_final_push_release.md)。
