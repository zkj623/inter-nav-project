# Go2 导航与推箱 Demo

本轮目标：输入平面坐标，让 Go2 自主到达、绕过障碍并停稳，支持暂停、继续和人工接管。
使用 ROS 定位与 LiDAR 建图，通过 SportClient 输出机身速度，MCF 保持运行。
**点导航和认箱都使用 MID-360S 点云。默认只做点导航，首次短推通过现场箱体配置启用。**

已登记箱体的完整自主推箱接入与操作见[真机推箱交互](docs/interaction.md)，
实验设计和整体验收标准见[真机交互方案](docs/interaction_plan.md)。
在场地里边认箱、边走完三个停靠点，见[三站连续验收](#三站连续验收)。

以下设备端命令假定仓库位于 `~/inter-nav-project`，运行环境已安装；首次使用见文末。
所有 Python 命令都在 `~/inter-nav-project/deploy` 中执行，虚拟环境位于上一级的 `.venv-deploy`。
开发机使用已配置好的 `go2` SSH 别名；没有配置时，换成实际的 `用户名@设备地址`。
机器人需站稳，定位与雷达驱动正常运行。操作 `run` 的终端须支持交互，SSH 登录时保留 TTY。

## 启动与记录

排查墙距偏差、点云重影或 IMU 时，按[点云与 IMU 测试](docs/sensor_check.md)录制原始 ROS 数据。
其中包含三组静止墙距与一次缓慢转向；日常导航验收记录仍使用下面的 `record.py`。

在开发机开三个终端，分别登录同一台 Orin，再用 tmux 保留各自的程序终端。
下面的 `tmux new` 只在首次创建会话时执行；已有会话请按“断线重连”接回。
**tmux 中的 run 不会因 SSH 断开而自动暂停。** 主动离开前先按 `p` 暂停；意外断线时由现场遥控器接管。

### 终端 1：启动 MID-360S 和导航实验

在开发机登录：

```bash
ssh go2
```

登录后创建 run 会话：

```bash
tmux new -s go2-run
```

进入 tmux 后执行：

```bash
bash ~/fishbot_multirobot_sim/deploy/go2_real/scripts/run_mid360s_lio.sh start
source ~/unitree_ros2/setup.sh
cd ~/inter-nav-project/deploy
source ../.venv-deploy/bin/activate
python run.py
```

点导航、认箱和推箱共用 MID-360S 的配准点云。启动时在终端确认显示「点云 `/bot1/cloud_registered_sparse`」。建图和 `view` 也用这路点云。Swarm-LIO 已把点配准到 `bot1/world`，程序用同一扫描时刻的 `/bot1/lidar_slam/odom` 确定机身和雷达的位置。启动时保持静止，等程序定好地面和起点。雷达安装位置采用支架标称尺寸。

建图时，每个方向保留最近的障碍，并用实际测到的激光标记空地。建图、标空地和找路都只用离地 28 cm 及以下的点。多帧认箱单独保留箱顶附近的点。首次推箱前，程序用当前扫描核对箱面。

固定起点周围有一块人工确认的空地。以启动时的机身中心为原点，范围是后方 45 cm、前方 85 cm、左右各 40 cm。第一帧建图时填入一次，随后扫到障碍会立即标出。换起点时，在 [导航配置](configs/navigation.yaml) 调整 `startup_clear_area`。填 `null` 就关闭这项设置。

等待出现“实验坐标系已固定”，且状态为
`观测=ready 建图=True 最近错误=None`，再在地图中确认目标附近和行进通道。
按 `n`，输入 `1,0`，按回车，开始前方 1 米的点导航。

输入目标或按 `r` 后，先显示“正在准备导航路径”，此时尚未启用运动。
先完成路线及首轮局部控制准备，再启用运动，并用新的定位和点云检查下一条速度命令。
对于地图范围内尚未探明通路的目标，机器人会先沿已观测的通道探索。
未知边界离障碍太近时，机器人会选择能看见边界的安全观测点，优先沿 Voronoi 路线前往。新点云确认通路后，机器人自动继续前往原目标。
如果当前地图既没有通往目标的路线，也找不到可达的观测点，机器人停下并保留目标和地图。地图更新后可按 `r` 重新规划。
运行中需要重新生成全局路线或交接交互技能时，会提示“正在停稳后规划”。
没有箱体的例行前沿检查使用当前全局地图的连通性查询，不为查询本身停车。
普通导航不再根据上一轮计算耗时预测性停车；实际命令或观测过期仍会停止。交互技能的预算逻辑保持原有规则。
程序确认停稳、完成规划，再用新的定位与点云复核后继续当前目标，无需重复输入 `n`。
普通导航复核按源观测的实际有效期判断，不把超过一个 100 ms 控制周期直接视作恢复失败。
如果新观测下没有可执行路线，则保持停止，地图更新后按 `r` 重新规划。
`record` 保留规划交接、命令入队与运动进程接收确认，以及控制周期各阶段耗时。
运行中的命令超时仍会停车并锁定，查明原因后需按 `r` 显式继续。

默认启用前置相机视频预览，不参与语义识别；不需要画面时加 `--camera none`。

### 终端 2：打开地图

在开发机另开终端，登录并转发网页端口：

```bash
ssh -L 8080:127.0.0.1:8080 go2
```

登录后创建 view 会话：

```bash
tmux new -s go2-view
```

进入 tmux 后执行：

```bash
cd ~/inter-nav-project/deploy
source ../.venv-deploy/bin/activate
python view.py
```

保持 SSH 连接，在开发机浏览器打开 <http://127.0.0.1:8080>。
`-L 本地端口:远端目标地址:远端端口` 将开发机的端口转发到 Orin 上的 view。
若本地 8080 已被占用，把参数换为 `-L 8050:127.0.0.1:8080`，浏览器改开
<http://127.0.0.1:8050>；view 仍使用 8080。只需一个 SSH 连接转发该本地端口。
这里不加 `-N`，以便登录后启动或接回程序；`-N` 只建立隧道，不打开远程终端。

界面上方并排显示全局路线/局部碰撞地图和历史点云，下方显示 RGB。地图使用与仿真一致的
分层配色、机器人轮廓、目标与路线标记；按“放大地图”可展开查看。
点云默认显示离地 **10–28 cm** 的点，地图用这个高度带判断障碍。点击高度按钮可一起查看近地点，最低到地面下 **10 cm**。箱顶单独用于认箱，地图上的箱框显示它的位置和朝向。录制保存原始观测，回放按所选配置过滤。
**判断当前障碍以导航地图为准**；历史点云可能保留已移动物体的位置。
关闭相机时没有 RGB 画面，不影响点导航。



## 点云认箱与查看

点导航和只观察模式都可以用 `--interaction-config configs/box_30x80x30.yaml --box-window` 查看登记箱体。只观察时加 `--observe-only`。打开 `view.py`，地图上会出现绿色实线框和箱号（如 `box-1`）。框按箱底的实际大小和朝向画。Go2 转身、暂停或换目标时，箱位保留。新扫描确认位置变化后，框会移到新位置。重启 `run.py` 会建立新地图。

## 断线重连

以下适用于 Orin 仍在运行、tmux 会话和程序未退出的情况。重新打开三个开发机终端：
run、record 使用 `ssh go2` 登录；view 使用上面的带 `-L` 命令登录，以恢复网页转发。
登录后，分别执行：

| 终端 | 接回命令 |
|---|---|
| run | `tmux attach -d -t go2-run` |
| view | `tmux attach -d -t go2-view` |
| record | `tmux attach -d -t go2-record` |

`-d` 会断开旧的 tmux 客户端，接回原终端；不会重启程序。刷新浏览器即可恢复 view。
接回后先查看程序状态，不要重复执行启动命令。若之前按 `p` 暂停，确认现场状态后再按 `r` 继续。
三个程序均在 Orin 本机运行；仅开发机 SSH 断开时，tmux 内的 record 可以继续记录本机 run。

| 操作或现象 | 处理 |
|---|---|
| 查看保留的会话 | 在 Orin 执行 `tmux ls` |
| 暂时离开 tmux | 先按 `Ctrl+b`，松开后按 `d`；程序继续运行，run 应先暂停 |
| 程序已退出，但 tmux 会话还在 | 接回后在原 shell 中重新启动该程序 |
| 提示找不到会话 | 先检查进程；确认对应程序已退出，再按启动步骤创建会话 |
| 本地端口占用 | 关闭旧的转发连接，或换用 8050 等空闲本地端口 |

若之前直接用普通 SSH 启动，没有使用 tmux，无法通过新建 tmux 接回旧终端。
在 Orin 检查当前进程：

```bash
pgrep -af 'python.*(run|view|record)\.py'
```

普通终端挂断被识别后，run 会进入停止和退出流程，view、record 也会退出；
网络中断不一定立即被识别，不能仅凭断线判断机器人已停。若旧 run 仍在且无法接回，
先由现场接管，再正常结束旧 run，避免重复启动。
重新启动 run 会重建地图、重设坐标原点，不恢复旧任务。重新启动 record 会生成新记录目录，
已保存的数据仍在，但中断期间的记录不能保证补齐。record 的数据源退出或更换会话时也会结束记录，需重新启动。

## run 按键

普通模式下按键立即生效，无需回车；只有坐标输入需要回车确认。

| 按键 | 功能 |
|---|---|
| `n` | 停止并取消当前任务，输入 `x,y`，回车启动新目标 |
| `p` | 暂停，保留当前目标 |
| `r` | 继续暂停的任务，重新规划 |
| **空格** | 停止并取消任务；输入坐标时也有效 |
| `o` / `m` | 停止并取消任务，回到观察，保留地图 |
| `Esc` | 退出坐标输入，不恢复刚才的任务 |
| `q` / `Ctrl+C` | 停止自主输出并退出 run |

**坐标输入中不要加空格。** 此时 `q`、`p` 等字母会作为输入文本；先按 `Esc` 返回普通模式，
再按命令键。`Ctrl+C` 可以直接退出。

## 坐标怎么填

每次启动 run，用第一组有效观测固定本轮坐标系：起点为 `(0,0)`，
**X 正方向是启动时的前方，Y 正方向是启动时的左方，单位为米。**
机器人转向、暂停、换目标都不会改变这个坐标系；重新启动 run 会建立新的原点和地图。

| 输入 | 目标位置，相对本轮起点 |
|---|---|
| `1,0` | 前方 1 米 |
| `2,-1` | 前方 2 米、右方 1 米 |
| `0,0` | 返回起点 |

### 调整实验边界

默认从起点向前留 5 米、向后留 1.2 米、向左留 0.9 米、向右留 2.6 米。
改场地时，在 `configs/navigation.yaml` 调整 `mapping.x_limits` 和 `mapping.y_limits`，每行按最小值、最大值填写。改好后，把机器人放回约定起点并朝向正前方，重新启动 `run.py`。启动窗口会显示本轮边界。

```yaml
world_boundary: true
mapping:
  x_limits: [-1.2, 5.0]
  y_limits: [-2.6, 0.9]
```

开启边界后，`view.py` 的导航地图、局部碰撞地图和累计点云只显示框内。蓝框是场地边界，白色是已看到的空地，深灰色是障碍，灰色是未知。调整上面的坐标就能改变显示范围。建图仍保留框外的雷达观测，激光落在框外时也能更新它经过的框内地面。导航建图的高度上限是 28 cm。

Go2 只在框内找路和推箱。选择探索方向时，跳过框外和贴墙太近、机身无法停靠的未知格子。其他未扫到的区域仍可探索。发出速度前还会检查转弯和刹车时的机身范围。

目标在边界外或落入边界的路线净空区时，终端会提示把目标往内移。当前路线净空是 0.30 米，按 0.10 米栅格判定。例如 `0.2,0.7` 距左边界只有 0.20 米，`0.2,0.4` 距左边界 0.50 米。边界内尚未观测的目标仍会触发探索。

## 三站连续验收

把机器人放在起点，朝约定的正前方。箱子平放，底面 **30 × 80 cm，高 30 cm**。让雷达看清箱顶轮廓或两个相邻侧面。可以沿箱底贴两小段胶带，方便对照箱子有没有真的移动。希望第一段就验到推箱时，把箱子摆在会挡住通道的位置，同时留出可以把它推开的空间。

在 Orin 的 `deploy` 目录启动一次正常点导航。以下配置用 LiDAR 认箱。首次搜索区在起点前方 0.5–2.2 m，从右侧 1.1 m 到左侧 0.8 m，覆盖原图的 A、B 箱位。实际箱位变化时，把 `search_region` 改到箱子起始位置附近，让箱子中心离边界留一点余量。雷达按形状找箱子，搜索区应避开尺寸相近的家具。[箱体配置](configs/box_30x80x30.yaml)

```bash
python run.py --interaction-config configs/box_30x80x30.yaml --box-window
```

这份场地配置只选地图上方的 30 × 30 cm 端面。Go2 走到箱子上方，沿箱体长轴向地图下方（实验坐标 −Y）推。端面略有转角时跟随实测法线。输入目标后，Go2 停稳等待点云确认箱位和上方站位，有路就自动出发，按 `p` 可暂停。途中用最近几帧箱顶稳定站位，单帧跳动会沿用原计划。在当前位置能够转身和横移对中时就停下转身，再用新扫描确认机头对准端面。对准后锁定机头间隙和速度，沿机身正前方以 20 cm/s 起步，以最高 35 cm/s 接近箱面。里程计走完初始间隙后，向底盘请求 50 cm/s 的推箱速度。从底盘首次发送前进指令开始限制接近时间。

若端面正前方空间不足以转身，规划器会检查左右各 32 cm 的站位，选择能转身并横移到端面中心左右 5 cm 内的位置。用里程计沿起步朝向的位移判断机头走完初始间隙。到达预计箱面后单独计时，目标推进行程约 53.3 cm，对应约 1.52 秒。机身提前走完预定行程时也会停车。推后停稳并收到 SDK 停止回执后，地图清除旧箱框。导航用停车后的点云选择能安全退出膨胀区的方向，净空足够就继续前往原目标。

在 `view.py` 看「前往箱边」「转向选定箱面」「停稳核对箱面」。等扫描、等箱位测稳或站位路线受阻时，页面会显示原因。运动端成功发出第一条向前顶箱的速度后，事件记录里会出现 `push_speed_sent`。推后显示交回导航，下一次确认箱位后地图显示新箱框。完整推开通道使用本机实测的接触参数。[完整推箱配置](docs/interaction.md#4-启用完整交互导航)

`run.py` 选定推箱时会打印「导航选中推箱」和箱号。第一条向前顶箱的速度发给 Go2 后会打印「已向 Go2 发送顶箱速度」。机身行程记录在 `timed_push_elapsed.forward_travel_m`。箱子实际移动了多少，需要对照推前和推后重新识别的位置。

另开 `view.py` 看现场，需要留存这趟验收时，从第一站开始前开同一个 `record.py`。在 run 里等「实验坐标系已固定」和「建图=True」。按 `n` 发第一个目标，每站到达并停稳后再按 `n` 发下一个。全程沿用起点坐标。

| 在同一趟里看什么 | 通过时能看到什么 |
|---|---|
| 认箱 | 起步前站稳。核对实线框和箱底的长边方向。转身或换站后，地图应保留同一箱号。 |
| 找路和推箱 | 确认 Go2 从上方顶住短端面向下推，对照箱底胶带和网页上的实测位移。通道打开后，再看 Go2 是否继续去原目标。 |
| 完成三站 | 沙发旁 → 书桌旁 → 鞋柜旁。三站都停稳，`events.jsonl` 中有三个成功的 `task_result`。要求实推的轮次还要核对对应任务的 `skill_reports` 和现场箱位。 |

同一份 `events.jsonl` 里，`box_window_result` 记录多帧认箱结果，`perception_result` 记录接触控制使用的当前扫描，`decision` 记录所选路线或动作。

启动后先让机器人站稳。30 cm 高的箱子用两段互不重叠的点云确认。站稳时每段最多积累 2 秒。两个侧面清楚时可以直接认箱。上方短端面场景也可以用平坦、边缘清楚的 30 × 80 cm 箱顶确认箱位。认箱保留到离地 46 cm，以便看见箱顶并排除过高的物体。确认后优先用最近 0.20 秒、0.35 秒的回波更新位置，移动时最多回看 1 秒。网页会显示本次确认所用的「两个侧面」「顶面 + 侧面」或「顶面」。

箱框一直显示在本轮地图上。多帧认箱的最新观测有效期是 0.35 秒。短暂遮挡时，详情显示「采用地图箱位」。转向上方短端面时以 6° 为瞄准目标。机身停稳后，7° 以内可进入箱顶确认和横移对中。靠近后可以用当前箱顶回波和靠近机器人的短边核对端面中心，横移对中后再顶箱。这份场地配置的顶面接触证据从扫描采集时刻起有效 0.38 秒。点云标记的是扫描结束时间，程序从上一帧的结束时间起计算这一帧的年龄。只看到一个箱面时，同一帧要量到箱面的两端，还要看到两端外的激光越过箱体深度。靠近矮箱时，若激光先落地，也可以用绕过两端的地面回波核对箱边。推箱所需的空地由地图单独检查。

要在 Orin 上按原速回看，把录制目录填入下面的命令。回放会按原来的时间送入点云，并计入机载计算耗时。`events.jsonl` 中的 `published_at` 是结果可见的时刻，`expires_at` 是位置过期的时刻。

```bash
python run.py --interaction-config configs/box_30x80x30.yaml --box-window --replay "<单次记录目录>" --realtime
```

若起点仍在地面坐标 `(160,90)` cm、朝白帘，前两站可按原图输入 `4.0,0`、`4.0,-1.4`。按上面的实验边界，第三站需要往场内移，可先确认 `0.2,0.4` 是否有空地停靠。场地变化时，用每站相对起点的前向距离、左向距离重新填写，单位米，右边取负。

## 点导航验收顺序

需要单独排查基础点导航时可参考以下操作。全程开启 record，操作者持遥控器监护。

1. **观察地图**：静止时检查墙面与障碍位置；短距离运动和转向后再检查，确认没有影响通路判断的错位。
2. **短距往返**：`n` → `1,0` → 回车，等待到达并停稳；再 `n` → `0,0` → 回车。建议重复三轮，用现场标记核对实际落点。
3. **转向与绕障**。选已观测且有足够通路的目标，例如 `2,-1`，确认能绕开固定障碍并到达。
4. **暂停与接管**：途中测试 `p` / `r`、空格取消，以及本机已配置的遥控接管键。接管后不应自行恢复自主运动。
5. **结束并核对记录**：在 run 按 `q`，等待 record 完成，检查该次记录目录中的结果。

默认到达条件是距离目标 **小于 0.25 m**，并通过连续约 **0.4 s** 的实测停稳检查。
还需要运动进程报告 `stopped`，并在现场确认机器人停止。

| 记录 | 核对内容 |
|---|---|
| `events.jsonl` | 每个目标的 `task_result` 事件中 `result.success=true`；对应的 `motion_state` 事件中 `state=stopped` |
| `run_summary.json` | `recording_complete=true`；最后任务的 `run_summary.task_result.success=true`；`run_summary.last_autonomous_stop_confirmed=true` |
| `observations/`、`frames/` | 定位、点云、导航地图、路径和现场对应情况 |

导航任务显示 `completed` 表示已到达目标并停稳。上方端面推箱场景还要求停车后实测到箱子位移。导航失败显示 `failed` 和原因，例如 `world_boundary_stop`。summary 顶层的 `completed` 表示会话正常收尾，每个导航目标的结果见 events 中的 `task_result`。
`hardware_validated` 不会自动变为 true，真机验收结论需要结合现场表现和记录给出。

分析实验前，先按文件修改时间确认最新一轮，将整个记录目录下载到本机并校验，再分析本地副本。
机器人日期不正确时，要结合其当前时钟和会话信息辨认记录；目录名不能作为新旧顺序的依据。

## 常用配置与排查

在 deploy 目录下，配置位于 `configs/`；改完后重新启动 run。

| 配置文件 | 当前点导航设置 |
|---|---|
| `robot.yaml` | 网卡 `eth0`，定位 `/bot1/lidar_slam/odom`，点云 `/bot1/cloud_registered_sparse` |
| `navigation.yaml` | `interaction_enabled: false`；到达距离 `0.25 m`；地图分辨率 `0.1 m` |
| `navigation.yaml` | 速度上限：前向 `0.8 m/s`、侧向 `0.3 m/s`、转向 `0.9 rad/s` |
| `navigation.yaml` | 导航障碍距地面 `0.10–0.28 m`，导航点云保留 `−0.10–0.28 m`，路线净空和障碍膨胀半径均为 `0.30 m` |
| `navigation.yaml` | 推箱前，箱面附近已知空地要累积足够的障碍观测才会改变全局路线。`box_map_occupied_threshold` 默认是 `2.25`。本地避障从第一帧起响应。 |
| `robot.yaml` / `runtime.yaml` | 数据最大年龄 `0.4 s`；命令有效期 `0.35 s` |
| `interaction.yaml` | 登记箱体、LiDAR 跟踪和 SDK 接触参数；默认未启用、无登记箱体 |

运动进程还会按 `runtime.yaml` 的上限限速；调整速度时同时核对两处配置。
前向与侧向速度按同一比例限幅以保留平移方向，角速度独立限幅；转向达到上限不会额外压低线速度。
导航在加速度平滑及碰撞检查前应用这些上限，线加速度与角加速度分别限制。
导航高度范围外的障碍不由此地图层表达，现场应使用平地、无台阶的验收区域。
更换设备、重置里程计或改变地面参考后，复核地面高度和 LiDAR 外参。

在 deploy 目录、已加载环境的设备终端中，可先做以下检查；两条命令均不发运动指令：

```bash
python run.py --check
python run.py --diagnose --duration 10 --output /tmp/go2-diagnostic.json
```

`--check` 检查依赖和配置，退出码为 0 不等于 ROS、DDS 或硬件已就绪；
`--diagnose` 实际订阅 ROS，检查收到的数据。

| 现象 | 先检查 |
|---|---|
| `观测=waiting` / `missing_sensor_data` | 定位和雷达驱动、话题、TF、时间配对及数据新鲜度 |
| `建图=False` | 有效点云、地面高度和 LiDAR 原点标定 |
| 目标被拒绝 | 坐标格式、地图边界、障碍占据，以及终端给出的具体原因 |
| `运动未启用` / `rejected` | SDK 反馈、网卡、机身状态和遥控接管状态 |
| `control_deadline_missed` | 上一条速度指令到期时，下一条还没准备好，Go2 会停车。查看记录里停车前的点云年龄和每条指令的计算耗时。 |
| `planning_hold:…:local_turn_search` | Go2 停稳后检查整个机身有没有转身空间。探索点走不通时，会试另一条路或换一个探索点。新点云确认可以起步后，继续前往输入的目标。 |
| `decision_expired` / `command_timeout` | 记录中的观测年龄、规划耗时、命令时限和运动状态；查明原因后再恢复 |
| 运动后墙面重影或通道错位 | 定位、点云配准和时间同步；固定实验坐标系不会修正这些偏差 |

## 首次安装与其他工具

设备端使用 Ubuntu 20.04 / ROS 2 Foxy 对应的系统 Python 3.8：

```bash
source ~/unitree_ros2/setup.sh
cd ~/inter-nav-project/deploy
bash scripts/install.sh
```

安装脚本在仓库根目录创建 `.venv-deploy`，安装 CPU 运行依赖；进入 deploy 后用
`source ../.venv-deploy/bin/activate` 激活。ROS、传感器驱动、定位和
`unitree_sdk2_python` 需在设备上就绪；脚本不安装或启动这些组件。

在 Orin 上运行 `tmux -V` 检查 tmux；未安装时执行：

```bash
sudo apt install tmux
```

需要同步代码时，在开发机仓库的 deploy 目录执行，替换实际设备地址和路径。
先预览，再应用；应用前停止设备上的 run：

```bash
bash scripts/sync.sh go2 /home/unitree/inter-nav-project
bash scripts/sync.sh go2 /home/unitree/inter-nav-project --apply
```

同步会补齐 `deploy/configs/` 中缺少的文件，并列出内容有差异的设备配置。已有标定、速度和验收配置按设备版本保留。旧版 `box_30x80x30.yaml` 若缺少箱面设置，会按该场景的上方短端面执行。设备专用配置也可放在仓库外，
启动时用 `--config-dir /绝对路径/配置目录` 指定。目录内需包含 `robot.yaml`、`navigation.yaml`、`runtime.yaml`；使用登记箱体交互时还需 `interaction.yaml` 及其引用的接触参数文件。

在 deploy 目录、已激活环境的终端中，其他常用入口为：

| 用途 | 命令 |
|---|---|
| 无硬件合成演示，5 秒后退出 | `python run.py --demo --camera none --demo-seconds 5` |
| 实际记录离线回放，不发送运动指令 | `python run.py --replay /绝对路径/单次记录目录 --task navigate --goal 1 0 --output /tmp/go2-replay` |
| 独立 SDK 短时运动验收 | `python run.py --motion-test` |

`--goal` 仅用于离线回放；真机目标通过 `n` 输入。回放使用保存的观测，不模拟机器人对命令的响应，不能代替闭环验收。

原始观测由独立线程在每帧点云到达时处理（MID-360S 点云和里程计均约 10 Hz），耗时规划期间也继续工作；record 保存观测线程按平均 `tick_hz`（默认 10 Hz）选出的帧，以及每次导航决策实际使用的帧。默认配置下，MID-360S 每来一帧新的扫描，导航就可以计算下一条速度指令。重复送达的同一帧不能为普通导航续期。view 的显示最多约 5 Hz，不决定观测记录频率。记录中的 `observations.jsonl` 与 `frames/` 分别用于原始回放和显示对照；完整性检查包含 `missing_observations`，不为缺失的数据补帧或更新时间戳。
`--motion-test` 与正常 run 分开运行，不启用地图或避障；按 `a` 准备，再按 `f` 前行、`j` 左转或 `t` 测试命令超时停车，空格停止、`q` 退出。
